# Бот школьной столовой для MAX

Python-бот собирает заказы родителей на следующий учебный день и после дедлайна отправляет администратору Excel-таблицу.

## Что реализовано

- регистрация родителя: класс `8МК` или `2Б`, затем ФИО ребёнка;
- сообщение с выбором питания в 15:00;
- варианты «Завтрак», «Обед», «Завтрак + обед» и «Ничего не заказывать»;
- повторное напоминание в 16:30 только тем, кто не ответил;
- изменение выбора до 17:00;
- отчёт после 17:00 с колонками «Класс», «ФИО», «Завтрак», «Обед»;
- заявка на роль администратора и одобрение/отклонение владельцем;
- сохранение пользователей, заявок и заказов в SQLite;
- защита от повторной плановой рассылки после перезапуска;
- Long Polling для локальной проверки и HTTPS Webhook для production;
- полностью контейнерный запуск, включая опциональный Caddy для HTTPS.

В пятницу заказ создаётся на понедельник. Суббота и воскресенье по умолчанию пропускаются. Это меняется через `SCHOOL_DAYS_ONLY=false`. Государственные и школьные каникулы бот автоматически не знает.

## Создание бота в MAX

По текущим правилам MAX создать чат-бота можно из верифицированного профиля организации, ИП или самозанятого — резидента РФ. Бота создают на платформе MAX для партнёров, отправляют на модерацию, затем получают токен в разделе **Чат-боты → Перейти → Расширенные настройки → Настроить**.

Полезные официальные страницы:

- [создание и модерация чат-бота](https://dev.max.ru/docs/chatbots/bots-create/create);
- [обзор Bot API](https://dev.max.ru/docs-api);
- [получение событий через Webhook](https://dev.max.ru/docs-api/methods/POST/subscriptions);
- [отправка сообщений](https://dev.max.ru/docs-api/methods/POST/messages);
- [загрузка файлов](https://dev.max.ru/docs-api/methods/POST/uploads).

Проект использует актуальный API-домен `https://platform-api2.max.ru` и передаёт токен в заголовке `Authorization`.

## Быстрый запуск для проверки

1. Создайте настройки:

   ```bash
   cp .env.example .env
   ```

2. Запишите токен в `MAX_BOT_TOKEN`. Если вы ещё не знаете свой `user_id`, временно укажите `OWNER_USER_ID=0`.

3. Запустите бота в режиме Long Polling:

   ```bash
   docker compose up --build -d
   docker compose logs -f bot
   ```

4. Откройте бота в MAX, нажмите «Начать» и отправьте `/id`. Запишите полученное число в `OWNER_USER_ID`, затем примените настройку:

   ```bash
   docker compose up -d --force-recreate bot
   ```

5. Родитель выбирает класс и отправляет ФИО ребёнка. Пока утверждённого администратора нет, ему показывается кнопка «Стать администратором». Заявка придёт владельцу с кнопками одобрения и отклонения.

Long Polling подходит для разработки. Если у токена уже осталась Webhook-подписка, один раз задайте `POLLING_DELETE_WEBHOOKS=true`, запустите контейнер, а затем верните `false`.

## Production с HTTPS Webhook

MAX требует публичный HTTPS endpoint на порту 443, сертификат доверенного центра и ответ HTTP 200 не позднее 30 секунд. В проекте есть Caddy, который автоматически получает TLS-сертификат.

1. Направьте DNS-запись домена на сервер и откройте входящие порты 80/443.
2. В `.env` задайте:

   ```dotenv
   BOT_DOMAIN=bot.example.ru
   WEBHOOK_URL=https://bot.example.ru/webhook
   WEBHOOK_SECRET=длинная_случайная_строка_без_пробелов
   ```

3. Запустите:

   ```bash
   docker compose -f compose.yaml -f compose.webhook.yaml up --build -d
   ```

Приложение сверяет `X-Max-Bot-Api-Secret` через безопасное сравнение и сразу отвечает MAX, обрабатывая событие в фоне.

Официальная документация также требует добавить сертификат Минцифры в доверенные для обращений к новому API-домену. В образе уже установлен системный пакет `ca-certificates`. Если хостинг не доверяет цепочке `platform-api2.max.ru`, добавьте выданный Минцифры корневой сертификат в доверенное хранилище вашего образа или передайте контейнеру актуальный CA bundle через `SSL_CERT_FILE`; не отключайте TLS-проверку.

## Настройки

| Переменная | Значение по умолчанию | Назначение |
|---|---:|---|
| `MAX_BOT_TOKEN` | — | токен бота MAX |
| `OWNER_USER_ID` | — | пользователь, который принимает заявки администраторов |
| `CLASSES` | `8МК,2Б` | классы через запятую |
| `PROMPT_TIME` | `15:00` | первая рассылка |
| `REMINDER_TIME` | `16:30` | напоминание не ответившим |
| `DEADLINE_TIME` | `17:00` | закрытие и отправка Excel |
| `TIMEZONE` | `Europe/Moscow` | часовой пояс расписания |
| `SCHOOL_DAYS_ONLY` | `true` | пропуск выходных |
| `WEBHOOK_URL` | пусто | полный адрес `/webhook`; пусто означает Long Polling |
| `WEBHOOK_SECRET` | пусто | секрет входящих Webhook-запросов |
| `DATABASE_URL` | SQLite в `/app/data` | строка подключения SQLAlchemy |

После изменения расписания перезапустите контейнер. Для реального школьного использования также подготовьте политику обработки персональных данных и ограничьте доступ к серверу и резервным копиям базы.

## Команды

- `/start`, `/menu` — открыть меню;
- `/id` — показать MAX user ID;
- `/report` — получить отчёт на ближайшую дату (владелец/администратор);
- `/report 2026-09-01` — получить отчёт за указанную дату;
- `/help` — краткая справка.

## Разработка и тесты

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
ruff check .
pytest
```

SQLite хранится в Docker volume `bot-data`. Не удаляйте volume при обновлении, если хотите сохранить пользователей и заказы.

Текущий MVP хранит одного ребёнка на один MAX-аккаунт родителя; данные ребёнка можно заменить через меню.
