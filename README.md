# Бот школьной столовой для MAX

JavaScript-бот на официальной библиотеке [`@maxhub/max-bot-api`](https://github.com/max-messenger/max-bot-api-client-ts).
Он собирает заказы родителей на следующий учебный день и отправляет Excel-отчёты
создателю и преподавателям.

## Возможности

- несколько детей у одного родителя, в том числе из разных классов;
- кнопочный список детей и отдельная карточка действий для каждого ребёнка;
- выбор завтрака, обеда, обоих вариантов или отказа отдельно для каждого ребёнка;
- напоминание тем, кто не ответил;
- изменение заказа до дедлайна;
- два отдельных отчёта для создателя — по одному файлу на каждый класс;
- отдельный отчёт по своему классу для каждого преподавателя;
- управление детьми своего класса для преподавателя и всеми детьми для создателя;
- обычный родительский режим преподавателя и создателя, а также отдельный круглосуточный
  тестовый режим создателя;
- отдельное расписание начала, напоминания и окончания заказов для каждого класса;
- преподаватель настраивает только свой класс, создатель сначала выбирает нужный класс;
- хранение данных в SQLite;
- работа через Long Polling без домена и открытых портов.

В пятницу заказ создаётся на понедельник, выходные пропускаются. Часовой пояс —
`Europe/Moscow`.

## Настройка

Создайте `.env`:

```bash
cp .env.example .env
```

Заполните значения:

```dotenv
MAX_BOT_TOKEN=токен_чат_бота
CREATOR_USER_ID=123456789

TEACHER_1_ID=
TEACHER_2_ID=

CLASS_1=8МК
CLASS_2=2Б
PROMPT_TIME=15:00
REMINDER_TIME=16:30
DEADLINE_TIME=17:00
```

`TEACHER_1_ID` получает отчёт только по `CLASS_1`, а `TEACHER_2_ID` — только по
`CLASS_2`. Любой ID преподавателя можно оставить пустым: бот продолжит работу, а
создатель всё равно получит общий отчёт.

Чтобы узнать ID, пользователь отправляет боту `/id`. После добавления ID в `.env`
пересоздайте контейнер.

## Запуск в Docker

```bash
docker compose up --build -d
docker compose logs -f bot
```

После изменения `.env`:

```bash
docker compose up -d --force-recreate bot
```

База хранится в Docker volume `bot-data` и сохраняется при пересборке образа.

## Локальный запуск

Нужен Node.js 20.19 или новее:

```bash
npm install
npm start
```

## Команды

- `/start`, `/menu` — открыть меню;
- `/list` — показать кнопочный список детей;
- `/id` — показать MAX user ID;
- `/help` — показать справку.

Служебные команды не публикуются в общем меню MAX и не показываются обычному
родителю в `/help`:

- `/report` и `/report 2026-09-03` — отчёт; создатель получает отдельный файл каждого класса,
  преподаватель — только файл своего класса;
- `/role` — переключить служебную панель в обычный режим родителя и обратно; доступен
  преподавателю и создателю;
- `/test` — круглосуточный тест заказов и добавления детей; доступен только создателю.

Все основные действия продублированы inline-кнопками. Преподаватель может просматривать,
редактировать и удалять детей только назначенного ему класса. Создатель может управлять
всеми детьми. Удаление требует отдельного подтверждения.

Расписания классов независимы. Если преподаватель меняет время своего класса, это не
влияет на другие классы. Родителю с детьми в разных классах бот показывает каждое
расписание отдельно, а уведомления и дедлайны применяет по классу ребёнка.

При первом запуске этой версии старая тестовая схема SQLite очищается: прежняя база была
рассчитана только на одного ребёнка у родителя и с новой моделью несовместима.
